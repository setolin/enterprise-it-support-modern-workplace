# Scope and Boundaries

## In scope

- Entra ID identity and group design.
- Joiner, mover and leaver lifecycle procedures.
- Windows endpoint and Intune-aligned policy design.
- Local ITIL ticket model and ten reproducible scenarios.
- PowerShell support automation with safe simulation mode.
- Metrics based only on repeatable lab tests.
- Technical, recruiter and interview documentation.

## Out of scope

- Production deployment or representation as employment experience.
- Real users, customers, patient data or corporate tenants.
- Purchasing licences or services.
- Publishing to GitHub, LinkedIn or other external platforms.
- Bypassing MFA, security controls or approval processes.

## Status labels

| Label | Meaning |
|---|---|
| Implemented | Built and validated locally in this repository or an authorised lab tenant |
| Simulated | Reproduced with controlled fictional data to model an enterprise workflow |
| Documented | Designed and explained, but not executed due to access/licensing constraints |

## Lab assumptions

The lab can use local Windows and PowerShell tooling without exposing secrets. Microsoft cloud capabilities are treated as documented until tenant access and licensing are confirmed. Any future cloud test must use a separate lab tenant, fictional identities and least-privilege permissions.
